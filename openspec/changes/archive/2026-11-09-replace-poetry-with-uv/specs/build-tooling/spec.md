# Spec Delta

## Purpose

Defines how the scan-pdf project is packaged, locked, and built: all project metadata lives in standard `pyproject.toml` (PEP 621 / PEP 735), the package is built with uv's native `uv_build` backend, dependencies are locked in a committed `uv.lock`, and local development, pre-commit, and CI all drive the environment through uv on a Python >= 3.11 floor.

## ADDED Requirements

### Requirement: Project metadata uses PEP 621
The project SHALL declare name, version, description, authors, license, readme, `requires-python`, and runtime dependencies in the `[project]` table of `pyproject.toml`, with the console script exposed via `[project.scripts]`.

#### Scenario: Package builds from standard metadata
- **WHEN** `uv build` runs in the project root
- **THEN** a wheel and sdist are produced using only `[project]` metadata and the `uv_build` backend, with no `[tool.poetry]` section present

#### Scenario: Entry point is installed
- **WHEN** the built wheel is installed into an environment
- **THEN** the `scan-pdf` command is available and invokes `scan_pdf.cli:run`

### Requirement: Python floor is 3.11
The project SHALL require Python >= 3.11 via `requires-python = ">=3.11"`, and all tooling configuration (ruff `target-version`, mypy `python_version`, pyupgrade pre-commit args) and the CI test matrix SHALL target 3.11 and newer only.

#### Scenario: Older Python is rejected
- **WHEN** `uv sync` runs with Python 3.10 selected
- **THEN** resolution fails because `requires-python` excludes 3.10

#### Scenario: CI does not test 3.10
- **WHEN** the build workflow matrix is evaluated
- **THEN** it contains 3.11, 3.12, and 3.13 but not 3.10

### Requirement: Dev dependencies live in a default dependency group
The project SHALL declare dev dependencies (pytest, pytest-mock, pytest-cov, mock, assertpy, mypy, ruff) in the PEP 735 `[dependency-groups]` table under `dev`, and uv SHALL install that group by default (`[tool.uv] default-groups = ["dev"]`).

#### Scenario: Fresh sync includes dev tools
- **WHEN** `uv sync --locked` runs in a clean checkout
- **THEN** pytest, mypy, and ruff are all importable via `uv run` without extra flags

### Requirement: Package source lives in src layout
The project SHALL place the package at `src/scan_pdf/`, moved without editing file contents, keeping the module name `scan_pdf` unchanged.

#### Scenario: Module identity is unchanged by the move
- **WHEN** tests `import scan_pdf`, CI runs `pytest --cov=scan_pdf`, or the installed `scan-pdf` entry point runs
- **THEN** all resolve to the installed `src/scan_pdf` package, because they reference the module, not the filesystem path

### Requirement: Package is built with the uv_build backend
The build system SHALL use `build-backend = "uv_build"` with `requires = ["uv_build>=0.13.7,<0.14.0"]` and its default src module root (no `module-root` override), and SHALL set `[tool.uv] package = true`.

#### Scenario: Src layout builds by default
- **WHEN** `uv build` runs with the package at `src/scan_pdf/` and no `[tool.uv.build-backend]` override
- **THEN** the wheel and sdist contain the `scan_pdf` package

### Requirement: Path-based tooling follows the src layout
Tooling that addresses the package by filesystem path SHALL use the new location: mypy SHALL set `mypy_path = "src"` alongside `packages = ["scan_pdf"]`, and `sonar-project.properties` SHALL set `sonar.sources=src/scan_pdf/`.

#### Scenario: mypy type-checks the source tree
- **WHEN** `uv run mypy` runs with `mypy_path = "src"` and `packages = ["scan_pdf"]`
- **THEN** mypy checks the `src/scan_pdf` sources directly instead of resolving the installed package (which lacks a `py.typed` marker)

#### Scenario: SonarCloud scans the moved source root
- **WHEN** SonarCloud analyzes the project
- **THEN** `sonar.sources=src/scan_pdf/` covers the package at its new location

### Requirement: Dependencies are locked in uv.lock
The project SHALL commit a `uv.lock` file generated by `uv lock`, SHALL delete `poetry.lock`, and CI SHALL install with `uv sync --locked` so a stale lockfile fails the build instead of silently updating.

#### Scenario: Stale lockfile fails CI
- **WHEN** `uv sync --locked` runs while `uv.lock` is out of date with `pyproject.toml`
- **THEN** the command exits non-zero without modifying the lockfile

#### Scenario: No Poetry artifacts remain
- **WHEN** the repo root is inspected after migration
- **THEN** `poetry.lock` does not exist and no file references the Poetry toolchain

### Requirement: CI provisions uv instead of Poetry
The build, analysis, and pre-commit workflows SHALL install uv via the SHA-pinned `astral-sh/setup-uv` action (with cache enabled), run `uv sync --locked`, execute tests and tools via `uv run`, and build via `uv build`; the third-party `abatilo/actions-poetry` action SHALL be removed everywhere.

#### Scenario: Tests run in CI
- **WHEN** the build workflow runs on any matrix OS/Python combination
- **THEN** pytest executes through `uv run pytest` in the uv-managed environment and `uv build` produces the distribution artifacts

#### Scenario: Pre-commit workflow prepares the environment
- **WHEN** the pre-commit workflow runs
- **THEN** `uv sync --locked` completes before `pre-commit run --all-files`, so the system-level mypy hook resolves `uv run mypy`

### Requirement: Local hooks and Dependabot follow uv
The pre-commit mypy hook SHALL use `entry: uv run mypy` (still `language: system`), and `.github/dependabot.yml` SHALL track the `uv` ecosystem for `/` instead of `poetry`.

#### Scenario: Pre-commit hook runs mypy through uv
- **WHEN** `pre-commit run --all-files` executes the local mypy hook
- **THEN** mypy runs in the uv-managed project environment via `uv run mypy`

#### Scenario: Dependabot scans uv manifests
- **WHEN** Dependabot evaluates the repository
- **THEN** it checks `pyproject.toml`/`uv.lock` under the `uv` ecosystem and no longer watches a Poetry manifest
